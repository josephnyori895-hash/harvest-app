## 1. Reproduction of the reel-preview complaint

Harness: local worker (`wrangler dev --local`, seeded local D1 + local R2),
Chromium via `scripts/dbg-reel-harness.mjs`. Three cases, all with keys that pass
the worker's media-key validation:

| Case | Data | Preview result | Tap result |
|---|---|---|---|
| A | poster jpg + valid mp4 | poster painted (720×540), ▶ shown | `readyState 4`, playing, `currentTime` advancing |
| B | **no poster** + valid mp4 | canvas frame captured (320×240), ▶ shown | `readyState 4`, playing |
| C | poster + **missing** mp4 object | poster painted, ▶ shown | `error.code 4`, "Video could not be played", Retry offered |

Retry in case C re-attempts the load and correctly stays in the error state
(the object genuinely does not exist).

**Conclusion:** the two preview paths (`FeedMediaPreview` poster branch,
`VideoThumb` canvas fallback) and playback/retry behave correctly for valid
data. The "black/broken reel" state reproduces only when the media object is
missing or unreachable — i.e. an upload whose R2 object is gone, the media
signature expired, or the key never landed. That is the failure clients would
see, and it is currently indistinguishable from "no preview" because the
fallback surface is a dark panel.

**Production data check (read-only):** both live reels
(`488ee458…`, `d86d90a0…`) have a `poster_key` and the poster object exists in
R2 (3.1 KB jpg); both `hls_master_key` values are `.mp4` and both objects exist.
So production's *current* two reels are not broken by missing media. Any other
client reports imply objects that have since gone missing — which no read-only
check can confirm without the member's session.

**Not verified:** Android WebView / APK playback. Chromium evidence does not
transfer automatically; the APK has a different media stack.

Legend: **Done** (code + tests), **Partial** (code exists, gaps), **Not started**,

- Natural ratios with bounds are implemented (`MIN_RATIO 0.5`, `MAX_RATIO 1.91`,

- **Aspect-ratio bounds conflict with the spec for portrait video:** 9:16 media
  (0.5625) survives, but anything taller is cropped into 0.5 — reel-style
  vertical video could get bars. Not a break, but not "natural".
- Upload **retry idempotency is implemented** (`workers/src/routes/media.js:177`
  — a retried logical upload re-submits the same key and gets the original
  result back).
- Playback failures are visible with Retry (verified in case C above).
- Photo editor: `ImageAdjuster.tsx` + `AdminMedia.tsx` present; **preview parity
  with the published result is unverified**.

### G. Feed advertising — **Built, not live**
- Server interleaving and caps are written (`workers/src/routes/feed.js`,
  uncommitted): advert slots every `interval` organic items (default 6),

## 3. Release risk

1. Production assets are replaced **wholesale** on `wrangler deploy`
   (`[assets] directory = "./public"`): a bad build takes the site down, not just
   a feature.
2. `feed.js` writes to `advert_impressions`; deploying it before migration
   `0030` turns `/api/feed` into a 500 for signed-in members.
3. Migration `0030` is additive and safe **on its own** (new table only) — it can
   be applied before any code deploy and changes nothing users can see.

## 5. Local proof of the advert contract

```
page1 kinds: reel,reel,reel,post,post,post,advert,post,post,reel,post
render 2 adverts: [ 'qa-ad-1' ] | render 3 adverts: []
ADVERT FEED CONTRACT OK
```

That is one advert interleaved after six organic items, the configured body,
title, `image_url` and `cta_url` passed through unchanged, `Harvest Family`
attribution, and the two-appearances-per-member-per-day cap enforced on the
server at the third render.

## 6. What a defensible release needs

1. Apply `0030` (additive, reversible by dropping an unused table).
2. `wrangler versions upload` → preview URL; verify on a real phone: feed loads,
   reels preview + play, one advert renders with a working CTA.
3. Only then `wrangler deploy`, with health + `/api/feed` + index checks and
   `wrangler rollback` ready.
4. Advert content (title, body, image URL, CTA URL) supplied by the church before
   adverts can appear at all.
